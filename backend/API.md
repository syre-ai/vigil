# Vigil API contract (backend ⇄ frontend)

Base: `http://localhost:8000/api`. All JSON. Errors: `{ "detail": str }` with 4xx/5xx.
The backend serves precomputed scores (data/scores/*.parquet) + mutable state in SQLite (data/vigil.db: reviews, versions).

## Vocabulary (use exactly these words in UI copy)
- "assurance evidence prototype" / "prototype model" / "prototype version" (never "accredited"/"accreditation decision"/"deployed"/"significant" — a drift p-value is "descriptive"/"indicative", never "significant")
- "tested envelope" (conditions with enough evidence), "untested" (n below `thresholds.min_n`), "degraded" (a bucket's own role accuracy / detection recall / novelty rate is worse than the `ref_holdout` control batch's, by margin — see `/envelope`); a bucket's label matching the reference definition (Clear Skies / USA / off-nadir ≤25°) is surfaced separately as `in_reference_definition` and never exempts it from being "degraded" — status is evidence-only
- "novel" = chip failed the vigilance test against every known category (Fuzzy ART); vigilance calibrated by parent-image 8-fold cross-fitting within the reference set (no operational, held-out, or military data)
- "reference domain" = ref_train ∪ ref_calib (clear skies, USA, off-nadir ≤ 25°, no military aircraft)
- "control batch" = ref_holdout (same domain as reference, never used for fitting or calibration)
- Batches are "operational batches"; the synthetic batch (if present) is an "external-domain stress test"
- "localization" = role and novelty scores are computed on ground-truth aircraft boxes (oracle localization); detector recall/precision (`/eval.detection`, `Batch.detection`, `/envelope`'s `detection_recall`, `/tiles/{id}.detections`) are scored separately against those same boxes at IoU ≥ 0.5, never folded into the role/novelty numbers
- `confirm` feedback is recorded as analyst agreement and **never alters the model** (no prototype/ART update); `correct` feedback is recorded as analyst **disagreement** with the predicted role and assigns the chip a known class label (one of the current version's `classes`) — it **never alters the model** either, exactly like `confirm`; only `new_class` feedback fits anything
- `bad_box` feedback (no label) records that the detection's **localization** is wrong — the detector's box fuses two aircraft or truncates one — as distinct from a wrong classification; it **never alters the model**, is **never** used to fit a prototype/ART category (excluded from `new_classes` exactly as if it had never been reviewed), and is **never** a training negative (the chip stays scored, `used_in_fit` stays `false`) — see `vigil.pipeline.BAD_BOX_POLICY_NOTE`. Allowed for both `source`s; most useful for `det` (a detector-drawn box). Counts of `bad_box` among reviewed FLAGGED detections are a field estimate of detector **localization** error, alongside `not_aircraft`'s estimate of detector **precision** — see `reviewed_flagged` in the Field mode section
- `used_in_fit` = a chip whose embedding was used to fit an analyst class mean from analyst feedback — it and every chip from the same parent images are excluded from every evaluation metric (see `/eval`, `/versions/compare`) to avoid the model grading itself on the chips it just adapted to

## Core objects
```ts
type Batch = {
  id: string;            // "ref_holdout" | "off_nadir" | "foreign" | "haze" | "snow" | "military" | "synthetic"
  order: number;         // stream order
  name: string;          // human label, e.g. "Control (same domain)", "High off-nadir (>25°)"
  description: string;   // one sentence, how the batch was formed (from real metadata)
  condition: Record<string, string|number>; // e.g. {weather: "Snow", countries: "USA", off_nadir: "3–25°"}
  n_tiles: number; n_chips: number; n_parent_images: number;
  drift: {
    score: number; null_p95: number; p_value: number; n_boot: number; statistic: string;
    // statistic = "mean 5-NN cosine distance to reference"
    null_method: string; // e.g. "parent-image block bootstrap over out-of-fold reference tiles (8-fold by parent image); p-value indicative"
    calib_mean: number;       // out-of-fold mean of the same statistic over the reference set, for a plain descriptive comparison
    ratio_to_calib: number;   // score / calib_mean
  };
  novelty_rate: number;  // fraction of chips flagged novel at calibrated vigilance
  role_accuracy: number | null; // on chips whose true role is a known (civil) class — evaluation-only, GT-based
  detection: { recall: number; precision: number; n_gt: number; n_det: number } | null; // data/scores/detection_metrics.json's by_domain[batch_id]; null if that file is absent or has no entry for this batch (e.g. "synthetic", not yet detector-evaluated)
  conf_shift: { ref_mean: number; batch_mean: number; ks_p: number } | null; // role-head confidence shift
};

type Chip = {
  ann_id: number; tile_id: number; batch_id: string; version: string;
  bbox: [number, number, number, number];  // x,y,w,h pixels in the 512×512 tile
  chip_url: string; tile_url: string;
  role_pred: string; role_conf: number;    // nearest-prototype role + softmax(cos/tau) confidence. For a civil prediction this is softmax over the three civil class means; for an analyst-claimed chip (novel + nearest one of an analyst class's labeled exemplars, see ADAPTATION_RULE) it is softmax over the UNION of civil class means + each analyst class's own exemplar mean (display-scale confidence only -- the exemplar rule itself, not this mean, decided the assignment), using the same fitted tau -- so role_conf is always one comparable probability scale, never the raw nearest-exemplar similarity (kept separately in scores parquet as `analyst_sim`/`analyst_margin`, not yet exposed on Chip)
  novelty: number;                          // 0..1, higher = more novel (1 - best ART match)
  is_novel: boolean; art_category: number | null;
  knn_dist: number;                         // baseline score, mean 5-NN cosine dist to reference
  umap: [number, number] | null;
  partial: number;                          // 0..1, fraction of the aircraft's true extent that falls inside this tile (RarePlanes annotations.parquet's `partial`; 1.0 = fully inside)
  truncated: boolean;                       // true iff this annotation is cut off by the tile edge (partial < 1); RarePlanes annotations.parquet's `truncated`
  used_in_fit: boolean;                     // true if this chip's embedding was used to fit an analyst class mean (analyst feedback) — excluded from evaluation metrics along with its parent image's chips
  detected: boolean | null;                 // this chip's ground-truth box, matched (IoU≥0.5) by the detector's own output — from data/scores/detections.parquet's kind="gt" rows; null if detections.parquet is absent or carries no row for this chip (e.g. reference-domain chips, which the detector isn't evaluated against)
  meta: { airfield: string; country: string; weather: string; off_nadir: number; gsd: number; wingspan_m: number | null };
  // evaluation-only fields (UI must label them "ground truth — evaluation only"):
  role_true: string | null;
  review: Review | null;
};

type Review = {
  source: "gt" | "det";    // "gt" = a ground-truth chip (ann_id is a real annotations.parquet ann_id, the historical/benchmark case); "det" = a detector chip (field mode -- ann_id here actually carries a det_id, see POST /review below). The two id spaces are independent (backend/app/db.py keys reviews on (source, ann_id)), so a gt review and a det review that happen to share a numeric id never collide.
  ann_id: number; action: "confirm" | "new_class" | "not_aircraft" | "skip" | "correct" | "bad_box";
  label: string | null; note: string | null; ts: string; version_applied: string | null;
  predicted_role: string | null;    // the chip's role_pred at the moment this review was POSTed (snapshot, never updated after the fact except by re-reviewing) -- read from the GT scores parquet when source='gt', from {version}_det.parquet when source='det'
  predicted_version: string | null; // the current version id at the moment this review was POSTed
};

type Version = {
  id: string; created: string; classes: string[]; n_feedback: number; note: string;
  n_confirm: number; n_new_class: number; n_not_aircraft: number; n_correct: number; n_bad_box: number; // feedback actions folded into this version, by kind
  assign_min_conf: number; // this version's POST /adapt `assign_min_conf` (0 = off, the default) -- see the Field mode section
};

type AnalystDisagreement = {
  n_reviewed: number; n_confirm: number; n_correct: number; n_new_class: number; n_not_aircraft: number; n_skip: number; n_bad_box: number;
  disagreement_rate: number | null; // n_correct / (n_confirm + n_correct), null if that denominator is 0
  by_pair: { from_role: string; to_role: string; n: number }[];              // (predicted_role -> corrected label) counts, sorted desc by n
  by_predicted_role: { role: string; n_confirm: number; n_correct: number; disagreement_rate: number | null }[];
};
```

| GET | `/envelope` | `{ dimensions: { name: string; buckets: { label, n_chips, n_images, n_parent_images, novelty_rate, role_accuracy, detection_recall\|null, control_delta: {role_accuracy\|null, detection_recall\|null}, in_reference_definition: boolean, status: "tested"\|"untested"\|"degraded" }[] }[] , thresholds: {min_n, degraded_margin, novelty_multiplier, control: {role_accuracy, novelty_rate, detection_recall, n_chips, n_parent_images}} }` — dimensions: weather, off_nadir (≤15, 15–25, >25), country (USA/other), gsd (<0.35, ≥0.35), aircraft size (wingspan class). Every bucket is computed over **operational batches only** (`ref_holdout`, `off_nadir`, `foreign`, `haze`, `snow`, `military` — grouped by the chip's own physical condition, e.g. weather, not by which batch it came from; a bucket legitimately pools rows from several batches that share that condition); `ref_train`/`ref_calib` (the model's fit set) are never included. `thresholds.control` = the `ref_holdout` batch's own metrics (role_accuracy/novelty_rate from `{version}_batches.json`, detection_recall from `detection_metrics.json`'s `by_domain.ref_holdout.recall`) — the evidence baseline every bucket's `status` is judged against. `status` = `"untested"` if `n_chips < min_n`; `"degraded"` if `role_accuracy < control.role_accuracy - degraded_margin`, or `detection_recall < control.detection_recall - degraded_margin`, or `novelty_rate > novelty_multiplier * control.novelty_rate`; else `"tested"` — **never** bypassed by a bucket's label matching the reference definition (that was a bug: buckets pooled reference-set chips with operational ones, and reference-matching labels were unconditionally marked "reference", skipping the checks). `in_reference_definition` = `true` for the "Clear Skies" weather bucket, the "≤15°"/"15–25°" off-nadir buckets, and the "USA" country bucket (`false` for every gsd/aircraft_size bucket, and for every other weather/off_nadir/country bucket) — purely informational, never a status. `control_delta` = `{role_accuracy: bucket.role_accuracy - control.role_accuracy, detection_recall: bucket.detection_recall - control.detection_recall}` (either `null` if either side is `null`). `detection_recall` is read straight from `data/scores/detection_metrics.json`'s `by_condition` (weather/off_nadir/country/gsd only — `aircraft_size` has no detection breakdown there, so its buckets always carry `detection_recall: null`) |

Every metric in this response excludes chips with `used_in_fit=true`. `detection` (from `data/scores/detection_metrics.json` + `detector_model.json`, neither versioned — the detector isn't re-fit by `/adapt`) is `null` if both files are absent; otherwise `by_role_group` = `{civil: {recall, n}, military: {recall, n}, scope}` (detector recall grouped by GT role, not role-head prediction, computed **within the military batch only** so both groups share the same collections — `scope` describes this, e.g. "within the military batch (same collections for both groups)"), `by_role_group_pooled` = same shape but civil recall pooled **across every detection-evaluated batch** instead (acquisition-domain confounded — civil aircraft come from every batch, not just the military one; `scope` describes this too) — `null` if `detection_metrics.json` doesn't carry `recall_by_role_group_pooled` yet (older shape: `by_role_group.scope` is then also `null`, since the old flat `recall_by_role_group` predates the military-batch-scoped/pooled split), and `by_batch` = `{batch_id: {recall, precision, n_gt}}` for every batch `detection_metrics.json` has an entry for. `analyst_disagreement` = `AnalystDisagreement` computed by `dataio.analyst_disagreement(version)` — restricted to reviews recorded against THIS version (see `/versions/compare`, whose `analyst_disagreement` is instead all-time). |

| POST | `/review/{ann_id}?source=gt\|det` body `{action, label?, note?}` | `Review` — `source` (default `gt`) selects which id space `ann_id` is in: `gt` = a real annotations.parquet `ann_id`; `det` = a det_id (field mode — see `GET /det/{det_id}` below); the two are independent, see `Review.source`. `action="confirm"` is recorded as analyst **agreement** and does not alter the model; `action="correct"` (label required, must be one of `/review/classes`, else 422 listing the allowed classes) is recorded as analyst **disagreement** with the predicted role and assigns the chip that known class label — it does not alter the model either, exactly like `confirm`; `action="not_aircraft"` on a `source='det'` chip drops it from THAT CHIP's det scoring only (excluded from `{version}_det.parquet` entirely on the next `/adapt`) — it is **never** a training negative for anything (fitting never uses detector chips regardless, see the Field mode section); only `action="new_class"` adds that chip's embedding as a labeled EXEMPLAR of an analyst class (Rule B, nearest-exemplar rule — never averaged into a single class mean for the assignment decision; trained ART categories and prototypes are untouched) — for `source='det'` this uses that det chip's own cached embedding (`data/emb/det_embeddings.npz`), never a GT embedding; `action="bad_box"` (no label) records a **localization** error (the box fuses two aircraft or truncates one) — the chip stays scored (never dropped, unlike `not_aircraft`) but is never fitted (excluded from `new_classes`/`used_in_fit` exactly as if never reviewed). Every POST snapshots the chip's current `role_pred`/current version onto the review's `predicted_role`/`predicted_version` (even on a re-review, overwriting the previous snapshot; `source='det'`'s snapshot comes from `{version}_det.parquet`) — the evidence `dataio.analyst_disagreement` groups by. |

## Notes for implementers
- Scores per version live in `data/scores/{version}.parquet` (one row per chip). The backend never recomputes embeddings; `/adapt` only refits prototypes/ART on cached embeddings.
- `vigil.pipeline.build_version()` always ends by calling `vigil.evaluate.evaluate(version_id)`, writing `data/scores/eval_{version}.json` — so `/versions/compare` can assume it exists for any version in `versions.json`.
- The scores parquet carries `used_in_fit` (bool), `neighbor_ids` (5 nearest ref_train `ann_id`s by cosine embedding distance) and `neighbor_dists` (their distances), alongside the existing columns.
- `Chip.partial`/`Chip.truncated` come from `data/rareplanes/annotations.parquet`'s own `partial`/`truncated` columns (joined in by `full_chip_table()`), not the scores parquet. `min_partial` (query param on `/batches/{id}/chips`, `/review/queue`, and `/batches/{id}`'s `top_novel`) is a **display/triage filter only** — it never touches scoring, `Batch` metrics, `/envelope`, or `/eval`, which always keep every chip (including mostly-truncated ones), so the model is never graded or calibrated on a filtered view.
- Detector-milestone files are **not** per-version (the detector is trained once, not re-fit by `/adapt`) and live directly under `data/scores/`:
  - `detector_model.json` — the model card: `{name, trained_on, val_split, val_map50, val_map50_95, val_precision, val_recall, conf_threshold, iou_threshold, note}`.
  - `detection_metrics.json` — `{conf_threshold, iou_threshold, by_domain: {batch_id: {n_gt, n_det, recall, precision}}, by_condition: {weather|off_nadir_b|country_g|gsd_b: {bucket: {n_gt, n_det, recall, precision}}}, recall_by_role_group: {civil, military, n_civil, n_military, scope?}, recall_by_role_group_pooled?: {civil, military, n_civil, n_military, scope}}`. Buckets: `off_nadir_b` in `"<=15"`/`"15-25"`/`">25"`, `country_g` in `"USA"`/`"other"`, `gsd_b` in `"<0.35"`/`">=0.35"`, `weather` = the RarePlanes weather strings ("Clear Skies" etc). `by_domain` only has entries for batches the detector has actually been evaluated against (currently `ref_holdout`, `off_nadir`, `foreign`, `haze`, `snow`, `military` — not `synthetic`, and never the reference domain itself). `recall_by_role_group_pooled` and `recall_by_role_group.scope` are optional (added when the pipeline rescoped civil-vs-military recall to compare within the military batch rather than pooling civil aircraft from every batch) — `dataio.detection_eval_summary()` degrades gracefully to the old flat shape (no `scope`, no pooled key) if they're absent, see `/eval`'s `detection.by_role_group`/`by_role_group_pooled`.
  - `detections.parquet` — one row per (tile, box): `kind="gt"` rows (`ann_id, tile_id, domain, tp`, `tp` = matched at IoU≥0.5) mirror `annotations.parquet` for the batches above; `kind="det"` rows (`x1,y1,x2,y2,conf,tp`, plus `ann_id` if matched to a GT box, else null/NaN) are the detector's raw output.
  - All three degrade to `null`/`None`/empty (never a 503) wherever the backend reads them — see `dataio.detector_card()`, `detection_metrics()`, `detections_df()`, `detected_by_ann_id()`, `tile_detections()`, `detection_eval_summary()`.
- Everything the UI shows must be computed from these files; no constants in the frontend.
- Frontend dev server proxies `/api` and `/media` to :8000 (vite.config.ts).

## Field mode
Per STATE.md's "Field mode" consensus and research/08-field-mode-proposal.md: an analyst-facing view of new, UNLABELED RarePlanes parent images, scored on the DETECTOR's own boxes (never ground truth) and grouped by **airfield × collection date**, never per-parent. `/api/collections*` is entirely additive — it never changes any existing endpoint above.

**Vocabulary (same rule as the top of this file):** "collection" = one airfield × collection-date (UTC day) group of new, unlabeled parent images — never a single parent image, never a ground-truth batch/domain name. "flagged" = a det chip whose `is_novel` is true (fails vigilance), exactly as elsewhere in this file. "the reference" / "labeled validation set" = `ref_train ∪ ref_calib ∪ ref_holdout` combined — the only labeled data in the field-mode story; `ref_holdout` alone is additionally the **control** a collection's flag rate is judged against (`reference_flag_rate`). A collection's `status` is evidence-only (same philosophy as `/envelope`'s bucket `status`) — never a batch/domain name, never ground truth, never a drift statistic (drift stays Benchmark-only, computed against a *known* domain, which field mode must not expose).

### Ids (read this once)
- A GT chip is identified by `ann_id` (a real `annotations.parquet` id). A detector chip is identified by `det_id` (its stable row order among `kind="det"` rows of `detections.parquet`). The two id spaces are **independent** and can collide numerically.
- Every det-chip payload ALSO carries `ann_id` **as an alias equal to `det_id`**, purely so the shared chip-drawer/review components can be reused; the `source` field (`"det"`) is what tells them apart. When you POST a review for a det chip you MUST pass `?source=det` (the path param is the det_id); reviews are keyed by `(source, ann_id)` in SQLite, so a det review never collides with a GT review of the same number.
- `group_id` identifies a collection: `slug(airfield) + "_" + YYYY-MM-DD` (see `CollectionGroup`), computed by one shared helper (`backend/vigil/grouping.py`) in both the API and the pipeline, so `FieldBlock.classes[].by_group[].group_id` always matches a `/collections` `group_id`.

### Field-mode objects
```ts
type CollectionGroup = {
  group_id: string;       // url-safe: slug(airfield) + "_" + date (see below)
  airfield: string; country: string; state: string;
  date: string;            // YYYY-MM-DD, collection date (UTC day)
  weather: string;
  off_nadir: number | null; gsd: number | null;   // mean over this group's distinct tiles
  lat: number | null; lon: number | null;         // mean over this group's distinct tiles
  n_parents: number; n_tiles: number;
  n_detections: number;    // count of det chips in this group (data/chips_det/index.parquet rows) — includes chips the analyst marked not_aircraft (they stay listed, with null scores, after the next /adapt)
  n_flagged: number;       // of those, how many are is_novel (fail vigilance)
  flag_rate: number | null;   // n_flagged / n_detections; null only if n_detections == 0
  excess_flagged: number | null; // n_flagged − n_detections × reference_flag_rate (how many more flagged than the reference rate predicts; negative = fewer); null if no usable reference rate
  p_value: number | null;  // one-sided binomial tail P[X ≥ n_flagged], X ~ Binomial(n_detections, reference_flag_rate) — INDICATIVE (tiles within a collection are correlated); null if no usable reference rate. Reported for every group incl. insufficient_data ones (UI: grey it out there)

type DetChip = {
  source: "det"; det_id: number;
  ann_id: number;          // == det_id — kept so the frontend can reuse GT-chip drawer/review components as-is (see "Ids")
  tile_id: number;
  bbox: [number, number, number, number];  // x,y,w,h pixels in the 512×512 tile
  conf: number;             // detector confidence for this box (always present)
  chip_url: string;         // "/api/det/{det_id}/image"
  tile_url: string;
  role_pred: string | null; role_conf: number | null;   // null = not scored by this version (e.g. reviewed not_aircraft)
  novelty: number | null; is_novel: boolean | null;
  knn_dist: number | null;
  meta: { airfield: string; country: string; weather: string; off_nadir: number | null; gsd: number | null };
  review: Review | null;    // same shape POST /review/{ann_id} returns — never role_true, never matched_ann_id
};

// /versions/compare `field.a` / `field.b` (one per version; null if that version predates field mode)
type FieldBlock = {
  n_detections: number;          // detector chips across NEW collections (every operational domain except ref_holdout)
  n_excluded_labeled: number;    // of those, used_in_fit (analyst-labeled, either source) — excluded from the counts
  n_excluded_same_parent: number; // other det chips from the SAME parent images as any labeled chip (det OR gt) — excluded too
  n_eligible: number;            // n_detections − the two exclusions; the denominator of assignment_rate
  classes: {
    label: string;               // analyst class name (from new_class feedback)
    n_labels_used: number;       // feedback items (both sources) that fed this class mean
    n_assigned: number;          // eligible det chips whose role_pred IS this class — DESCRIPTIVE, never "accuracy"/"recall"

  }[];

    label: "labeled control-set regression check";
    overall: number | null;      // accuracy_ref_holdout
    per_class: { cls: string; accuracy: number | null; n: number | null }[];
  } | null;
  reviewed_flagged: {             // field estimate of detector precision/localization error on FLAGGED (is_novel) det chips, from det-chip reviews of any action -- computed at build time by vigil.field.compute_field (see "Det-chip scoring" below); always present (all-zero/null default if this version's eval artifact predates the key, e.g. built before bad_box landed)
    n: number;                    // det-chip reviews (source='det', any action) on chips that WERE flagged
    n_not_aircraft: number;       // of those, action="not_aircraft" (false positive)
    n_bad_box: number;            // of those, action="bad_box" (localization error)
    field_precision_on_flagged: number | null; // (n - n_not_aircraft - n_bad_box) / n; null if n == 0

  labeled_collections: {          // DISPLAY ONLY -- never folded into `classes`/n_assigned/assignment_rate above. One entry per airfield x date collection containing >=1 analyst-labeled ('new_class') det chip.
    group_id: string; airfield: string; date: string;
    n_labeled: number;                 // that collection's own labeled (new_class) det chips -- the analyst's training exemplars
    n_bad_box: number;                 // of the collection's FLAGGED det chips, reviewed bad_box
    n_not_aircraft: number;            // of the collection's FLAGGED det chips, reviewed not_aircraft
```

A `DetChip`/`FieldBlock` deliberately carries **no** `role_true`, no `matched_ann_id`, no `domain`/`batch_id`/`domains`/`by_domain`, and no drift field — this is the whole point of field mode (an analyst reviewing unlabeled imagery has none of those). The backend test suite asserts this recursively on every analyst-view payload (`/collections*`, `/review/queue?source=det`, `/det/{id}` minus `neighbors`, `/versions/compare`'s `field`). `group_id`'s slug lowercases the airfield name and collapses every run of non-alphanumeric characters to a single `-` (e.g. `"Some Airfield, TX"` → `"some-airfield-tx"`), so `group_id = "some-airfield-tx_2026-03-04"`; two distinct airfields whose slugs happen to collide on the same date get a stable `-2`, `-3`, ... suffix rather than silently merging.

### Status rule (evidence-only, no size bias)
`status_rule` on `/collections` states it verbatim. `insufficient_data` if `n_detections < min_denominator (20)`; else a **one-sided binomial tail test** of `n_flagged` given `n_detections` against `reference_flag_rate` (the flag rate of `ref_holdout`'s own detector chips — the labeled control set): `p_value = P[X ≥ n_flagged]`, `X ~ Binomial(n_detections, reference_flag_rate)` (`scipy.stats.binom.sf(n_flagged − 1, n, p)`); `needs_review` if `p_value < p_threshold (0.01)`, else `nominal`. This replaced a `flag_rate ≥ 2× reference OR n_flagged ≥ 10` rule whose absolute count marked every big civil airport `needs_review` (21 flagged of 510 = 4.1% vs 3.1% → now `nominal`, p = 0.13) while a small collection with a real excess (18 of 66, p ≈ 1e-12) is caught. The p-value is **indicative, not inferential**: detector chips within a collection share tiles and a parent image, so they are correlated and the binomial understates uncertainty — UI copy must say "indicative", never "significant". **Guard:** if `reference_flag_rate` is `null` or `0` there is no tail to test against; `p_value`/`excess_flagged` are `null`, status falls back to `n_flagged ≥ 10`, and `status_rule` says so explicitly (`"... (Fallback: no usable reference flag rate ...)"`).

### Data model (built by a concurrently-developed det-chip milestone)
- `data/chips_det/index.parquet` — `det_id, tile_id, parent_id, domain, conf, x1,y1,x2,y2,w,h, matched_ann_id, path`. `domain` is the same domain vocabulary as elsewhere (`ref_train`/`ref_calib`/`ref_holdout`/`off_nadir`/`foreign`/`haze`/`snow`/`military`/`synthetic`) but this backend never surfaces it directly on a `/collections*` response — only used internally to tell new collections apart from the reference set. `matched_ann_id` (benchmark-only, IoU≥0.5 match to a GT box) is never read by this module.
- `data/scores/{version}_det.parquet` — `det_id, tile_id, parent_id, batch_id (= domain), role_pred, role_conf, novelty, is_novel, art_category, knn_dist, neighbor_ids, neighbor_dists, umap_x, umap_y, used_in_fit, analyst_sim, analyst_margin, conf`, scored by the SAME fitted role/novelty models as `{version}.parquet` — never used to fit anything. `analyst_sim` = 1 − the winning analyst class's nearest-exemplar cosine distance (0 if unclaimed); `analyst_margin` = that chip's 1-NN cosine distance to the labeled reference set minus the nearest-exemplar distance (0 if unclaimed) — see `vigil.pipeline.ADAPTATION_RULE`. Left-joined onto the det chip index (a det chip with no score yet — or one reviewed `not_aircraft`, which the next `/adapt` drops from this parquet — still counts toward `n_detections`, just not `n_flagged`; its `DetChip` scores are `null`).
- `data/rareplanes/tiles.parquet` — existing loader; supplies `airfield, country, state, weather, off_nadir, gsd, lat, lon, collection_date` (per-group values are the mean/first over that group's own tiles).
- Reviews on a det chip live in the SAME `reviews` sqlite table as GT-chip reviews (`backend/app/db.py`), tagged `source='det'` and keyed by the chip's `det_id` (reused as the review's `ann_id`, per `DetChip.ann_id` above) — read through `db.reviews_by_ann_id(source="det")`.
- Every loader above degrades to an empty/typed result (never a 5xx) if its file doesn't exist yet — `/collections*` works (with empty groups) before the det-chip milestone lands, exactly like every other file-backed endpoint in this document.

### Det-chip scoring (`backend/vigil/pipeline.py`) and the `field`/`control` eval blocks (`backend/vigil/field.py`)
- `data/chips_det/index.parquet` is built by `scripts/extract_det_chips.py` from `data/scores/detections.parquet`'s `kind="det"` rows (all confidences ≥ 0.25) — 15% padding, 224×224, same crop recipe as `scripts/extract_chips.py`. `det_id` is that file's own stable row order among `kind="det"` rows. `vigil.embed.embed_det_chips()` caches embeddings to `data/emb/det_embeddings.npz`, keyed by `det_id` (CLI: `python -m vigil.embed --det`).
- `vigil.pipeline.build_version()` fits PCA/min-max/Fuzzy ART/prototypes/tau/UMAP/kNN on reference **GT** chips exactly as before (fitting **never** uses detector chips, in the initial build or after adaptation), then scores every detector chip currently in the index with those SAME fitted models (transform only) → `data/scores/{version}_det.parquet`. `{version}_batches.json` gains a top-level `det` block: `{domain: {n_det_chips, flag_rate}, ..., reference: {n_det_chips_ref_holdout, flag_rate_ref_holdout}}` (`flag_rate` = fraction of that domain's det chips with `is_novel=true`; `reference` restates `ref_holdout`'s own numbers under field-mode-specific key names — descriptive only, not a claim of accuracy).
- Analyst feedback (`POST /review/{id}?source=det`, `action="new_class"`) adds that det chip's own embedding as a labeled EXEMPLAR of an analyst class (mixing `source='gt'` and `source='det'` labels under the same class name is supported: exemplars are drawn from whichever embedding space each labeled chip belongs to). A chip joins the class only via `ADAPTATION_RULE`'s nearest-exemplar rule (never a class mean) — see `vigil.pipeline._assign_roles`. `{version}_model.json` gains `analyst_class_label_counts: {label: {n_total, n_gt, n_det}}` — how many feedback items, by source, fed each analyst class — and `assign_min_conf` (this build's optional additional confidence gate, det chips only; `0` = off, the default).
- `used_in_fit` is marked in BOTH scores parquets where applicable (a det chip's own `used_in_fit` in `{version}_det.parquet`; a GT chip's own `used_in_fit` in `{version}.parquet`, only if a GT chip was itself labeled). The GT-eval same-parent exclusion (`vigil.evaluate._adaptation_exclusion_mask` / `EXCLUSION_METHOD`) now excludes parents of labeled chips from **either** source — `vigil.evaluate.labeled_parent_ids(version)` pools `gt_used_in_fit_parents` + `det_used_in_fit_parents`.
- `action="not_aircraft"` on a `source='det'` chip drops it from `{version}_det.parquet` on the next `/adapt` only — it is **never** a training negative (fitting never sees detector chips regardless of this exclusion).
- `eval_{version}.json` (a file on disk — the evaluation ARTIFACT, never served verbatim; the API's `FieldBlock` above is *composed from it* by `dataio.field_block()`, which drops the benchmark-only `domains`/`by_domain` keys and nests `control`) gains two blocks, computed by `vigil.field.compute_field()` and folded in by `vigil.evaluate.evaluate()`:
  - `field` (artifact shape, Benchmark/offline use only): `{ domains: string[] (off_nadir, foreign, haze, snow, military — "new collections", i.e. every operational domain except ref_holdout), n_detections, n_excluded_labeled, n_excluded_same_parent, n_eligible, classes: {label, n_labels_used, n_assigned, assignment_rate, by_group: {group_id, airfield, date, n_assigned}[] (top 10 collections by n_assigned, desc — det scores carry tile_id → tiles.parquet → airfield/collection_date, grouped with the same `vigil.grouping.group_id` as `/collections`)}[], by_domain: {domain: {n_detections, n_excluded_labeled, n_excluded_same_parent, n_eligible, classes (no by_group)}}, reviewed_flagged: {n, n_not_aircraft, n_bad_box, field_precision_on_flagged}, labeled_collections: [...] (see FieldBlock above), assign_min_conf: number | null, note: "assignments are descriptive; not ground-truth accuracy" }` — `n_assigned`/`assignment_rate` count UNLABELED, non-same-parent det chips in those domains whose `role_pred` is that analyst class; this is descriptive (no ground truth exists for a detector chip in field mode), **never** called "accuracy" or "recall". `domains`/`by_domain` are benchmark batch names and stay in this artifact only — `dataio.field_block()` drops them when composing the analyst-view `FieldBlock`. `reviewed_flagged` (`vigil.field._reviewed_flagged_block()`) is computed from ALL `source='det'` reviews in the SQLite reviews table (the one place `vigil/field.py` reads `backend/app`) at build time: `n` = reviews on chips that WERE flagged (`is_novel`) — looked up in this version's own `{version}_det.parquet` first, falling back to the review's snapshotted `predicted_version`'s det parquet for a chip since excluded by a `not_aircraft` review (which drops it from det scoring going forward); `n_not_aircraft`/`n_bad_box` are the subsets with those actions; `field_precision_on_flagged = (n − n_not_aircraft − n_bad_box) / n`, `null` if `n == 0`. `dataio.field_block()` always includes this key on the analyst-view `FieldBlock`, filling in the all-zero/null default for a version built before this key existed. `labeled_collections` (`vigil.field._labeled_collections_block()`, same current/historical flagged-status lookup as `reviewed_flagged`) is DISPLAY ONLY, never folded into `classes`/`n_assigned`/`assignment_rate`/`by_domain` above — see `FieldBlock.labeled_collections`. `assign_min_conf` is read straight off `{version}_model.json`.
  - `control` (artifact shape): `{ label: "labeled control-set regression check", accuracy_ref_holdout: number, per_class: {cls: {accuracy, n}} }` — the SAME ref_holdout GT-chip role-head numbers as `/eval`'s `role_head`, restated under this label for the field-mode story (a regression CHECK against the one labeled set, not an accreditation decision).
- `/versions/compare`'s `field` key = `{a: FieldBlock|null, b: FieldBlock|null, worst_regression}` — each side composed by `dataio.field_block(version)` from that version's `field` + `control` blocks (control nested as `FieldBlock.control` = `{label, overall: accuracy_ref_holdout, per_class: [{cls, accuracy, n}]}`, class names canonicalized like `/eval`).
- Verification script: `scripts/exercise_field_adaptation.py` drives the REAL HTTP path (`/collections` → `/collections/{tirana…}` → 6× `POST /review/{det_id}?source=det new_class "Military fighter"` + 1 confirm + 1 bad_box → `/review/queue?source=det` → `POST /adapt` (real `vigil.pipeline.build_version`) → `/versions/compare` → `/report`) against a scratch copy of `data/scores/` and a scratch sqlite db (`VIGIL_SCORES_DIR`/`VIGIL_DB_PATH` set before import), asserts every shape above, asserts the live `v1.parquet`/`versions.json`/`vigil.db` are unchanged, copies the outputs to `artifacts/rehearsal_field_v2/` (`eval_rehearsal_field_v2.json`, `rehearsal_field_v2_{model,batches}.json`, `rehearsal_field_v2_det.parquet`, `feedback.json`, `compare.json`, `collections_summary.json`) and deletes the scratch dir. ~4 min; the live app is never touched.
- `scripts/rebuild_last_version.sh`: undoes the top built version (v2+, never v1) on the LIVE app so it can be rebuilt under a different adaptation rule/parameter (e.g. a new `assign_min_conf`) without redoing the analyst's reviews — deletes that version's own `{version}.*`/`{version}_det.parquet`/`eval_{version}.json` files, drops it from `versions.json`, and resets every review with `version_applied` equal to it back to `NULL`, so the next `POST /adapt` folds in the exact same feedback again through the current code path. Refuses to touch `v1` or run with fewer than two versions recorded.


### Field review queue ranking (2026-09-06 evening)
`GET /review/queue?source=det` defaults to `strategy=collection` and `min_conf=0.5`: flagged detector chips with detector confidence ≥ min_conf (detector false positives are novel by definition and cluster at low confidence — 64% of flagged detections in new collections are false positives at median conf 0.36 vs 0.65 for real aircraft; `min_conf=0` disables the gate), ordered needs_review collections first (by excess flagged desc), then novelty desc within a collection. (This queue `min_conf` only filters what the analyst is SHOWN, unrelated to `POST /adapt`'s `assign_min_conf`, which gates what an analyst class may CLAIM at build time — see the Field mode section above.) Items in `collection` strategy also carry `airfield`, `date`, `group_status`, `group_n_flagged`. Without `source`, the GT queue defaults to `strategy=novelty` exactly as before. Marking false positives with `not_aircraft` is itself evidence: the fraction of reviewed flagged detections marked not-aircraft is a field estimate of detector precision on flagged detections. Marking a bad box with `bad_box` is the localization-error counterpart of the same idea: among reviewed flagged detections, `not_aircraft` estimates false-positive rate and `bad_box` estimates localization error (fused/truncated aircraft) — together they compose `field_precision_on_flagged` (see `FieldBlock.reviewed_flagged` above).

### Model health · retrain readiness (2026-09-06 late)
`GET /health` → `{ version, recommendation: "keep" | "patch" | "schedule_retrain", reasons: string[], indicators: Indicator[], rules: string[], note: "indicative; computed from field-available evidence and the labeled control set" }` with `Indicator = { key, label, value: number | null, display: string, status: "nominal" | "watch" | "retrain", rule: string, evidence: string }` (`backend/app/health.py`, own router). **Indicative only** — an input to a retraining decision, never the decision; UI copy says "indicative" and never "deployed"/"accredited"/"significant"/"recall". Uses only field-available signals plus the labeled control set; the same forbidden-key rule as every analyst-view payload applies. Every threshold is a module constant restated verbatim in `rule`/`rules` (the UI shows those strings, never restates them):
- `novelty_pressure` — share of new collections with status `needs_review`, overall and among the 30 most recent by date; status from the larger share: watch ≥ 10%, retrain ≥ 25%.
- `new_class_demand` — per analyst class: `n_labels` (new_class reviews, both sources), `n_collections_labeled` (distinct airfield × date groups those labels came from), `n_assigned` (latest field block), verified precision of that class's changed detections (previous → latest version, same `predicted_version`-scoped counting as `/versions/changes/summary`, per class). Emerging (1 collection) = nominal; recurring (labeled in ≥ 2 collections, or ≥ 5 verified-confirmed assignments across ≥ 2 collections) = watch; retrain if recurring and (≥ 20 labels, or verified precision < 60% with ≥ 10 verified).
- `detector_quality_field` — from the latest field block's `reviewed_flagged`: field precision on flagged and bad-box rate (`n_bad_box / n`). Fewer than 10 reviewed = insufficient evidence (nominal, said so in `evidence`); watch if precision < 60% or bad-box rate ≥ 25%; retrain if precision < 40%. Refreshes when feedback is applied (the block is computed at build time).
- `patch_safety` — largest per-class accuracy drop on the labeled control set (`control.per_class` in each version's eval artifact), v1 → latest AND across every consecutive step (so a drop-then-recover is still caught): nominal ≤ 1pp, watch ≤ 3pp, retrain > 3pp.
- Recommendation: keep if every indicator is nominal; patch if any is watch and none is retrain; schedule_retrain if any is retrain. `reasons` = one sentence per non-nominal indicator. Degrades (never a 5xx) when a version has no eval artifact: that indicator reports insufficient evidence. The report's analyst section opens with the same block ("Model health · retrain readiness (indicative)").
